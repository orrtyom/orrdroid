# Исходное техническое задание

1. Определение режима сети - бс, чс, авто (фарватер)
2. Пинг всех серверов (keqdroid) и отсекание только работоспособных (фарватер)
3. Автовыбор сервера среди всех подписокс учётом текущего состояния и истории задержек, разбросов и отказов, периодически проверка работоспособности выбранного сервера (как в Keqdroid)
4. замена сервера при заметно лучшем варианте, порог улучшения и минимальное время между переключениями;
5. Возможность скрыть нерабочие серверы из общего списка
6. объединение серверов из всех подписок в группы - по планируемому/определённому режиму сети, стране точки выхода, тегу/ключевым словам (пресет+кастом)
7. Создание цепочек серверов - как сервер-сервер, так и группа серверов - группа серверов (например, доступ к легальным сайтам в ru зоне во время работы белых списков)
8. Продвинутая маршрутизации
- выбор сервера исходя из условий - правила как в keqdroid + режим сети + возможность выбор не только конкретного сервера, но и цепочки из серверов/групп серверов/точке выхода, 
- больше пресетов маршрутизации, 
- подключение кастомного автообновляемого hosts (например от steven black), 
- просмотр, редактирование и отключение правил провайдеров подписки
- обращения к интерфесу TUN из рабочего профиля автоматически отбрасываются по UID
9. Интеграция Tailscale для доступа к своему Tailnet с поддержкой обфускации через AmnesiaWG 1.5+, а также реализацией остальных функций оригинального приложения
10. Закрытие максимума уязвимостей по документации https://github.com/xtclovver/RKNHardering

## Дополнения пользователя в чате

1. Основной репозиторий разработки и версий: https://github.com/orrtyom/orrdroid.
2. Автоматическая синхронизация настроек и подписок между телефоном, планшетом, компьютером, ТВ и другими телефонами.
3. В режиме синхронизации с главным устройством ведомые не могут переписать его настройки; альтернативный режим всех устройств добавлен ниже.

6. Оценить готовый форк Tailscale с AWG: https://github.com/LiuTangLei/tailscale-awg-installer (реальное ядро и мобильная обвязка вынесены в связанные репозитории).
7. Учесть существующий вход в Tailscale через Auth key в Karing.

Уточнённая интерпретация требований и ограничения находятся в PLAN.md и SYNC.md. Исходное ТЗ выше сохранено без смысловой правки.

## Дополнение 11 ноября 2026: синхронизация и LAN-прокси

11. Два выбираемых режима синхронизации настроек и подписок:
    - с главным устройством: одно устройство публикует, остальные получают; его настройки нельзя переписать с ведомого;
    - со всех устройств: редактирование на любом авторизованном устройстве, синхронизация последних изменений с учётом офлайна и конфликтов. Независимые правки сохраняются обе; старый backup не заменяет весь новый документ.
12. Варианты обмена: Tailnet, защищённая локальная сеть, шифрованная резервная копия/файл; внешние сервисы как отдельные адаптеры (в первую очередь WebDAV/Nextcloud, затем оценка S3 и синхронизируемых папок/облачных API). Выбор сервиса не меняет полномочия группы.
13. Доступ к SOCKS5 и HTTP-прокси Orrdroid из локальной сети: обязательные логин и пароль для обоих протоколов, выбор интерфейса/порта, копирование ссылки и QR с реквизитами. Анонимный режим запрещён. Раздача включается локально и не активируется автоматически от синхронизации.

Эти уточнения расширяют прежнюю модель единственного издателя: она сохраняется как отдельный режим. Политика слияния и каналы — [SYNC.md](SYNC.md), LAN-доступ — [LAN_PROXY.md](LAN_PROXY.md). Смена роли/режима не является обычной синхронизируемой правкой.

## Дополнение: выбор адреса проверки

14. Обязательный пользовательский HTTPS URL для проверки серверов через кандидат, включая контрольный ресурс, недоступный напрямую; пример пользователя — Instagram favicon. В простом режиме отдельно настраиваются общий и контрольный профили. В расширенном режиме — профили сервисов, связанные с Auto-группами и маршрутами. Успех Google не подтверждает Instagram/Telegram; успех Instagram не подтверждает Telegram. Результаты статуса, тела и протокольной доступности разделены. Подробности — [PROBE_PROFILES.md](PROBE_PROFILES.md).

15. Уточнение пользователя: для его сценария Instagram-проба подходит для поиска узлов Telegram. По умолчанию использовать общий профиль «Telegram + Instagram» с пользовательским Instagram URL; отдельная Telegram-проба опциональна. Это уточняет пункт 14: нейтральный URL не заменяет общий TG+Instagram-профиль, но отдельный TG-тест для допуска не требуется.

## Дополнение 12 ноября 2026 · маршрутизация в БС и ЧС

16. **БС.** Сначала применяется правило «Белые списки мобильной связи — напрямую». Сразу за ним поставить правило для всех остальных назначений, совпавших с `geosite:ru` **или** `geoip:ru`. Их трафик идёт через сервер с подтверждённым выходом в России.
17. **ЧС.** Напрямую идёт весь трафик, кроме сервисов из списков блокировок РКН, замедлений РКН и ограничений доступа из России. Для этих исключений использовать прокси. Для сервисов с ограничением доступа из России нужен подтверждённый выход за пределами РФ.

Порядок применения и критерии допуска пути описаны в [PLAN.md](PLAN.md#8а-пресеты-бс-и-чс).
