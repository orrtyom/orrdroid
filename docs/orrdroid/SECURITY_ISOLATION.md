# Изоляция Android VPN: уточнение плана

Редакция 0.2, 11 ноября 2026. Основание: предоставленный пользователем материал «Изоляция VPN на Android: CalyxOS, GrapheneOS и утечка через tun0» от 17 октября 2026 и проверка первичных источников/кода Keqdroid v0.36.0. Приложения и атаки на устройстве в этой работе не запускались.

Дополнение 0.3: сравнение v0.36.0 → v0.36.1 не содержит изменений `ConnectionOwnerServer.kt`, `owner_guard.dart` и рассмотренных owner-патчей. Изменения генераторов относятся к порядку маршрутов и связанному DNS/QUIC; исправление выявленных вопросов изоляции ими не подтверждено. База будущих испытаний — v0.36.1.

## 1. Три разных результата

1. Приложение видит интерфейс TUN или иной системный признак VPN.
2. Приложение, которому туннель не предназначен, может передать через него данные и узнать внешний адрес.
3. Приложение получает доступ к локальному SOCKS/HTTP-прокси или управляющему API.

Устранение второго и третьего сценария не означает скрытия первого. Список приложений VpnService задаёт маршрутизацию; сам по себе он не доказывает невозможность принудительного обращения к TUN. Сообщение GrapheneOS #7655 воспроизводит использование интерфейса VPN другого профиля; статус issue не является подтверждением поведения всех актуальных устройств.

Android 17 документирует блокировку межпрофильного loopback по умолчанию. Это не заявление о блокировке всех обращений к TUN и не изменение loopback внутри одного профиля. Поэтому пароль/контроль доступа к локальным endpoint остаются необходимыми.

## 2. Что уже реализовано в Keqdroid

В предыдущем плане эти механизмы были недооценены. Для v0.36.0 подтверждены следующие части:

| Компонент | Подтверждённое поведение |
|---|---|
| `ConnectionOwnerServer.kt` | Через Android API определяет владельца TCP/UDP; IPC по abstract Unix socket, обслуживает только собственный UID |
| `owner_guard.dart` | Выбирает `OwnerGuard.all` для Android TUN, API 29+ и режима, отличного от `allProxy`; в `allProxy` защита выключена |
| Xray owner patch + config generator | Передают исходный адрес назначения для lookup; правило по маркеру `keqdroid:outside-vpn` ставится до DNS/провайдерских правил |
| mihomo owner guard | Маркер владельца обрабатывается первым TUN-правилом; DNS hijack проверяется отдельно |
| mihomo handshake patch + sing-tun patch | Проверка перед завершением TCP-handshake; отрицательное решение даёт reset, а не успешное открытие с последующим закрытием |
| mihomo DNS addresses-only patch | В специальном случае неизвестного владельца разрешает только A/AAAA класса IN, прочие типы отклоняет |

Патчи и генератор конфигурации образуют систему. Нельзя заменить модифицированное ядро обычной сборкой и считать защиту сохранённой только потому, что настройка осталась в JSON. В M0 проверять применение патчей, итоговый конфиг и реальные бинарники.

## 3. Найденные границы и гипотезы для проверки

**Режим allProxy.** В комментарии к выбору защиты предполагается, что вне VPN нет приложений. Это предположение нельзя распространять на соседний Android-профиль без проверки. Именно этот сценарий становится первым негативным тестом. По одному выключенному флагу нельзя объявить доказанную утечку конкретной сборки: нужны попытка передачи и наблюдение на контролируемой цели.

**INVALID_UID не равен достоверно чужому UID.** API может не найти уже закрытый сокет, не видеть соединение или не сопоставить сокет с привязкой к интерфейсу. Существующий мост превращает INVALID_UID в специальный маркер, кроме DNS-исключений. Ошибку API/IPC, неизвестного владельца и явно запрещённого владельца в новой диагностике необходимо различать.

**DNS-исключения.** В режиме «только выбранные приложения» мост оставляет неизвестным владельца для адреса своего DNS и для порта 853 при включённом строгом Private DNS. Это эвристика назначения, а не доказательство происхождения от системного resolver. Фильтр A/AAAA устраняет конкретный канал TXT/CH, но не доказывает отсутствие всех DNS-каналов. Проверить запросы с уникальным именем к своей авторитетной зоне и поведение DoT к контролируемому endpoint. Учитывать, что авторитетный DNS часто видит адрес рекурсивного resolver, а не непосредственно IP выхода VPN.

**Ошибка owner service.** В mihomo-патчах запрет требует успешного ответа со специальным маркером; ошибка IPC не даёт такого запрета. В Kotlin исключение также превращается в пустой ответ. Xray получает ошибку/неизвестный процесс, а не гарантированное совпадение запрещающего правила. Это поведение с пропуском при ошибке следует проверить на реальном пути, не называть строгой изоляцией.

**Покрытие протоколов.** `getConnectionOwnerUid` поддерживает TCP/UDP, а не ICMP и произвольные IP-протоколы. Фрагменты и IPv6 extension headers требуют отдельной обработки. Формулировку из материала «протоколы кроме TCP/UDP проверяются так же» нельзя принимать буквально.

**Производительность.** В мосте есть четыре worker, в патчах — двухсекундный кеш. Само наличие worker не доказывает, что вызывающий путь TUN не ждёт ответа. Проверить предельный размер очереди, задержку новых соединений, повторное использование 5-tuple, свежий TCP SYN, смену политики и очистку кеша. Результаты стороннего PR нельзя переносить на Keqdroid без измерений.

## 4. Изменение требований Orrdroid

R1 переносится в M0–M1: аудит и воспроизведение имеющейся защиты, затем исправление подтверждённых пробелов до заявления о защищённой изоляции. M5 остаётся этапом расширенной регрессии при цепочках и новых путях. Это не задача «написать проверку UID с нуля».

Предлагаемый контракт строгого режима:

- До подтверждения разрешённого происхождения поток не передаёт прикладные данные через защищённый выход. Очередь ожидания ограничена по памяти, числу потоков и времени; переполнение не включает пропуск без проверки.
- Состояния `allowed`, `denied`, `unknown`, `lookup_failed`, `unsupported` различаются в диагностике. В строгом режиме неизвестность не превращается автоматически в разрешение; системные исключения требуют отдельного проверенного механизма.
- Сбой owner service вызывает явное состояние «изоляция не подтверждена» и восстановление службы/туннеля. Автоматическое отключение защиты ради доступности недопустимо.
- Для ICMP, фрагментов, системного DNS и входящих Tailnet-соединений определяется отдельная политика. Не обещать универсальную совместимость строгого режима с раздачей, входящими сервисами и всеми UDP-приложениями.
- Проверка происходит там, где ещё доступны исходные адреса потока: до утраты информации при проксировании, DNS hijack и переопределении назначения. Уже имеющийся native TUN Xray учитывается; не утверждать, что любой Xray-путь обязательно проходит через tun2socks.
- Совместимый режим сохраняется как явно отличный от строгого, с отображением фактических ограничений. Переключение между ними не должно происходить скрыто.

По итогам R1 решить, достаточно ли доработки существующего моста/правил или нужен более ранний общий фильтр. Не добавлять новый слой автоматически до воспроизведения проблемы.

## 5. Проверки, обязательные до закрытия R1

| Область | Сценарии |
|---|---|
| Профили | Основной → рабочий и обратно; Private Space; VPN в каждом профиле; allProxy/include/exclude |
| TUN | Принудительная привязка к интерфейсу, TCP и UDP, IPv4/IPv6; контроль фактической доставки на собственной цели |
| DNS | Свой TUN DNS, внешние адреса:53, TCP/UDP, A/AAAA/TXT/CH/HTTPS, Private DNS/DoT:853 |
| Неопределённость | Закрытый сокет, INVALID_UID, таймаут/обрыв Unix socket, исключение API, недоступный owner service |
| Кеш и нагрузка | Повтор 5-tuple другим сокетом, новый SYN, смена списка приложений/сети, лавина запрещённых потоков |
| Особые пакеты | ICMP, IPv4/IPv6-фрагментация, extension headers, PMTU и штатные системные ошибки |
| Tailnet | Ответы на входящее соединение, DNS/MagicDNS, собственный sync-listener, отсутствие доступа несопряжённых устройств |
| Localhost | SOCKS/HTTP/API в том же и другом профиле; Android до 17 и 17+; пароль и отключённые listener |

Проверять оба ядра, обычный и импортированный конфиг, AWG через mihomo и цепочки. Отдельно измерять время нового подключения, UDP loss, CPU и память. Не устранять сигнал детектора ценой поломки DNS/PMTU или скрытого прямого выхода.

Условия успеха: разрешённые сценарии работают; запрещённые потоки не достигают контролируемой цели; отказ службы владельца не превращает строгий режим в разрешающий; ограничения честно описаны. Ответ RST или видимый tun0 сами по себе не равны утечке внешнего адреса.

## 6. Источники и уровень уверенности

- [Android 17: cross-profile loopback](https://developer.android.com/about/versions/17/behavior-changes-all) — официально описано поведение loopback.
- [Android getConnectionOwnerUid](https://developer.android.com/reference/android/net/ConnectivityManager#getConnectionOwnerUid(int,java.net.InetSocketAddress,java.net.InetSocketAddress)) — документированные ограничения API.
- [GrapheneOS #7655](https://github.com/GrapheneOS/os-issue-tracker/issues/7655) — опубликованное воспроизведение на конкретной версии; собственных измерений нет.
- [sing-box #4009](https://github.com/SagerNet/sing-box/issues/4009) — различение неидентифицированных потоков; закрытый issue не является тестом готового клиента.
- [amneziawg-go PR #199](https://github.com/amnezia-vpn/amneziawg-go/pull/199) — при чтении открыт, не слит; автор описывает bounded queue, проверку владельца, измерения и ограничения. Использовать как инженерный материал, не как доказательство готовности всех Amnezia-клиентов.
- [ConnectionOwnerServer.kt](https://github.com/Lemonochka/keqdroid/blob/v0.36.0/android/app/src/main/kotlin/com/keqdroid/keqdroid/ConnectionOwnerServer.kt), [owner_guard.dart](https://github.com/Lemonochka/keqdroid/blob/v0.36.0/lib/utils/owner_guard.dart), [config_gen.dart](https://github.com/Lemonochka/keqdroid/blob/v0.36.0/lib/utils/config_gen.dart), [mihomo_config_gen.dart](https://github.com/Lemonochka/keqdroid/blob/v0.36.0/lib/utils/mihomo_config_gen.dart).

## 7. Разрешённый LAN-прокси

Дополнение 0.4: [LAN_PROXY.md](LAN_PROXY.md) разрешает только явно включённый, аутентифицированный LAN inbound. Его нельзя путать с обходом через чужой TUN. Проверить отказ SOCKS no-auth и HTTP/CONNECT без credentials, недоступность control API, IPv6, смену сети и отсутствие direct fallback. Синхронизация не включает раздачу и не меняет её локальный пароль. Защита TUN продолжает действовать независимо от LAN listener.
