# SOCKS5 и HTTP-прокси для локальной сети

Статус: обязательное дополнение ТЗ 0.4. Orrdroid позволяет другим устройствам использовать выбранный прокси-путь через телефон/ПК с приложением. Это прикладной proxy endpoint, не обещание раздать весь VPN через Android hotspot или маршрутизировать произвольные IP-пакеты без настройки клиентов.

## Граница первого этапа

E1-08 использует существующие listener Keqdroid и добавляет обязательные реквизиты в UI и обоих генераторах, полные URI и QR. При миграции включённая LAN-раздача без реквизитов отключается до настройки. Пароль внутреннего proxy остаётся отдельным.

Первая приёмка — Android, SOCKS5/HTTP и оба ядра. Группы как отдельные цели LAN и расширение на desktop/TV относятся к следующим работам M3P. Требования ниже к границам доступа, авторизации и отсутствию обходов применяются уже к E1-08.

## Поведение

- Отдельный переключатель «Доступ из локальной сети», по умолчанию выключен. Выбор интерфейса/адреса и порта; SOCKS5 и HTTP доступны отдельно либо через mixed-listener, если оба адаптера ядра обеспечивают одинаковые требования.
- **Логин и пароль обязательны** для обоих протоколов. Нет анонимного режима и обхода авторизации через альтернативный порт, SOCKS no-auth, HTTP CONNECT или второй listener. При первом включении сгенерировать пароль; редактирование с проверкой непустого значения.
- SOCKS5 CONNECT, HTTP forward proxy и HTTP CONNECT. UDP ASSOCIATE, remote DNS и IPv6 — отдельная проверяемая матрица поддержки; если вариант не поддержан ядром/платформой, явная ошибка без direct fallback.
- Выбор назначения: текущий VPN/Auto, группа либо цепочка. Входящие LAN-соединения имеют отдельный inbound tag и явную политику DNS/маршрутов. Правила по UID/пакетам телефона не выдаются за правила приложений удалённого клиента; если удалённый трафик должен идти direct, это отдельное правило.
- Переключение узла влияет на новые соединения; существующие сохраняются, где возможно, либо статус честно сообщает об обрыве. Падение ядра/пустая группа не отправляет трафик напрямую.

## Экран подключения

Показать статус listener, протокол, выбранный LAN-адрес, порт, логин, скрытый пароль, назначение и число подключений. Кнопки: показать/сменить пароль, копировать ссылку, показать QR, отключить доступ. Для меняющегося DHCP-адреса ссылка/QR обновляются; старый адрес помечается устаревшим.

Предлагаемый формат ссылки: `socks5://<encoded-user>:<encoded-password>@<host>:<port>` и `http://<encoded-user>:<encoded-password>@<host>:<port>`. Корректно кодировать Unicode, @, :, /, %, #; IPv6 в квадратных скобках. QR содержит ту же ссылку. Проверить совместимость с выбранными клиентами: не все приложения умеют импортировать URI/QR; рядом всегда доступны отдельные поля для ручного ввода. Разрешение DNS через SOCKS у конкретного клиента проверить отдельно, URI сам по себе его не гарантирует.

Копирование/показ QR выполняются только явным действием пользователя и включают credentials. Не записывать их в логи/аналитику/общую диагностику. Не размещать QR на публичном веб-интерфейсе; чистить clipboard по возможности без обещания удалить уже сделанные копии. Смена пароля инвалидирует старые ссылки; политика закрытия существующих сессий видна пользователю.

## Доступ и ограничения

Привязка к выбранному LAN-интерфейсу, доступ из настроенной локальной подсети; не слушать публичный/мобильный интерфейс автоматически. IPv6 не должен обходить ограничения IPv4. При смене сети или пропадании выбранного интерфейса перепроверить binding и остановить доступ, если прежняя политика неприменима. Автозапуск раздачи после перезапуска — отдельная локальная настройка.

Логин/пароль SOCKS5 и обычного HTTP-прокси сами по себе не шифруют канал авторизации. Для недоверенной сети предусмотреть доступ через Tailnet либо защищённый транспорт, совместимый с клиентом. Не называть обычный LAN SOCKS/HTTP защищённым от прослушивания.

Ограничить попытки авторизации и ресурсы клиента; предусмотреть лимит соединений, таймауты и отзыв доступа. Управляющее API ядра, синхронизация, debug и subscription export никогда не публикуются вместе с прокси. UPnP/публичный проброс портов не включаются.

Существующая owner-защита TUN сохраняется: разрешённые аутентифицированные LAN-входы отделены от запрещённого чужого TUN. Нельзя ради раздачи отключать UID guard для всего приложения. Не смешивать пароль локального измерительного proxy с паролем LAN.

Включение, bind и пароль раздачи — локальные настройки. Синхронизация общей конфигурации не открывает прокси на других устройствах. Перенос реквизитов по отдельному явному экспорту возможен позже, но не включён в обычную синхронизацию.

## Приёмка и этап

E1-08 выполняется после базового исполнителя и раннего R1 на Android с обоими ядрами. Расширение M3P добавляет отдельные цели и desktop/TV. Android hotspot/изоляция Wi-Fi-клиентов/OEM-ограничения проверяются отдельно: отсутствие доступного LAN-адреса даёт понятное сообщение, не фиктивную ссылку.

Обязательные тесты: отказ без credentials/с неверным паролем; SOCKS no-auth отвергнут; HTTP CONNECT не обходит авторизацию; передача данных и DNS; IPv4/IPv6; переключение/падение ядра без direct-утечки; смена сети; Unicode/IPv6 в URI и QR; отзыв пароля; закрытые control/sync API; отсутствие публикации после sync или импорта.
