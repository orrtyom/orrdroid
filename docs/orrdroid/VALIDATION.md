# Проверки стабильности и критерии выпуска

Статус: план испытаний. Приложения в рамках подготовки этих документов не запускались и на сети пользователя не измерялись. Числа ниже — стартовые критерии для согласования по результатам M0, не полученные показатели.

## 0. Приёмка первого этапа E1

Объём определён в [PLAN.md §2а](PLAN.md#2а-утверждённый-первый-этап). Базовые проверки ниже обязательны для alpha первого этапа. Разделы синхронизации, Tailnet, динамических групп/цепочек и самостоятельных сервисных профилей применяются при реализации соответствующих следующих этапов.

| Область | Проверяемый результат |
|---|---|
| Уровень 0 | Свой HTTPS URL сохраняется. Пакетные проверки всех узлов, подписки и цепочек работают. DIRECT/BLOCK/текущий/отдельный сервер, hosts/AdBlock/URL и AWG/mihomo сохраняют поведение |
| Backup | Новые поля проходят export/import. Старые правила мигрируют во «Всегда», ID, порядок и привязки сохраняются. Неизвестная новая схема отклоняется понятным сообщением |
| E1-01 | Пресет содержит проверенные домены/IP. Исходный справочный текст и ограничения аккаунтов не превращаются автоматически в широкие правила |
| E1-02/03 | Всегда/БС/ЧС фильтруются одинаково в обоих генераторах. Ручной режим не перезаписывается автопробой. Новые подключения получают подтверждённый набор правил и DNS |
| Отсутствие совпадений | В ЧС DIRECT, в БС текущий сервер. При неизвестном режиме чистой установки действуют «Всегда» и штатное «Всё остальное» профиля |
| E1-04 | Сопоставить Farvater и Orrdroid при чистой установке, известном/неизвестном режиме, ручном выборе, загрузке/отказе подписки, наличии кэша, первом подключении и смене физической сети |
| Физическая сеть | Пробы режима идут вне собственного VPN. Проверки серверов идут через конкретный кандидат. Результат старой сети не применяется |
| E1-05 | Сохранённая цепочка выбирается через mihomo, ID переживает переименование/backup/обновление. Проверяются весь путь и совместимость ступеней. Удаление, несовместимость и отказ дают явную причину, допустимый резерв либо BLOCK |
| E1-06 | БС — мобильный белый список DIRECT, далее RU geosite OR geoip через РФ, остальное текущий сервер. ЧС — ограничения для РФ через выход вне РФ, затем РКН через proxy, остальное DIRECT. При пересечении соблюдается более конкретное требование |
| Страна выхода | Проверяется именно назначенный выход, для цепочки последняя ступень. Контрольный запрос не уходит через GlobalAuto вместо проверяемого пути. Неизвестная страна не удовлетворяет обязательной географии |
| E1-07 | Фильтр можно выключить. Непроверенные и устаревшие не считаются подтверждённо нерабочими. Скрытые узлы сохраняются и перепроверяются |
| E1-08 | Пустые/неверные credentials отклонены для SOCKS5, HTTP и CONNECT. Валидация действует в UI и обоих генераторах, включая импорт backup. Старая раздача без реквизитов остановлена до настройки |
| LAN URI/QR | Одинаковый URI с корректным кодированием специальных символов/IPv6. Смена адреса обновляет ссылку. Управляющее API не публикуется, внутренний пароль не подменяется LAN-паролем |
| E1-09 | Кандидат из любой разрешённой подписки достижим независимо от её положения. Отключённые источники/узлы исключены. Соблюдены лимиты провайдера, ручной выбор, резерв и порядок маршрутов |
| E1-10 | Заголовки с зависшим/обрезанным телом не дают успешную проверку данных. Сервер, игнорирующий Range, не превышает клиентский бюджет чтения. Общий deadline ограничивает весь тест |
| Контракт ответа | Ожидаемый 204 успешен без тела, но не подтверждает объём. 200 с неверным телом, DNS/TLS/timeout/429 и отказ транспорта различаются. Оба ядра используют одинаковые критерии |
| Восстановление | После гибели процесса, перезагрузки и обновления сохраняется намерение держать VPN. Режим и обязательные выходы перепроверяются. Ручная остановка не отменяется автоматикой |
| Интеграция | Проверить Wi-Fi ↔ мобильная сеть, БС ↔ ЧС, экран выключен/Doze, массовый отказ цели, падение ядра, полную потерю сети и восстановление |

## 1. Честная исходная точка

На одинаковом устройстве, в одной сети и с одинаковыми узлами сравнивать зафиксированный Keqdroid и Orrdroid. Контролировать ядро, fragmentation/TLS, URL, DNS, IPv4/IPv6, правила и порядок тестов. Старые сохранённые пинги из разных бэкапов не использовать как доказательство выигрыша.

Стенд: собственные тестовые серверы/учётные записи, контролируемые HTTP-цели и воспроизводимые сетевые нарушения. Локальные журналы очищать от credentials, subscription URL, UUID, приватных ключей и пользовательского трафика до коммита. Проектные fixtures содержат только синтетические данные.

## 2. Основные метрики

| Метрика | Определение |
|---|---|
| Доступность | Доля времени, когда заданная прикладная проверка проходит; отдельно для общего доступа и конкретных сервисов |
| Восстановление p50/p95 | Время от контролируемого отказа до устойчиво работающего нового пути, а не до надписи «подключено» |
| Ложные переходы | Смена сервера при работавшем требуемом пути из-за ложной диагностики |
| Обрывы | Прерванные загрузки/длительные TCP и UDP-сессии на час работы |
| Работа в фоне | Те же показатели при закрытом UI, выключенном экране, Doze и смене сети |
| Стоимость | Байты проверок, CPU, память, число временных ядер/сокетов, батарея относительно baseline |
| Синхронизация | Время от публикации до получения/применения; число отказов валидации; отсутствие несанкционированной записи |

Низкий RTT не компенсирует рост времени без связи. Скорость оценивается вместе с доступностью и стоимостью переходов.

## 3. Обязательные сценарии Auto

| Сценарий | Ожидаемый результат |
|---|---|
| Один рабочий узел среди многих подписок | Найден независимо от положения подписки в списке |
| Все узлы исключены из GlobalAuto | «Нет допустимых кандидатов»; исключения не сбрасываются и запрещённые узлы не возвращаются в пул |
| Текущий узел умер, резерв доступен | Проверенный переход и подтверждение передачи по новому пути |
| Полностью нет физической сети | Backoff; нет массового накопления ложных отказов и бесконечных перезапусков |
| Сломалась одна тестовая цель | Нет необоснованного переключения всей группы |
| Заголовки пришли, тело зависло/обрезано | Быстрый тест и проверка данных дают разные корректные статусы |
| Captive portal/HTML-заглушка | Не принимается за доказанный доступ |
| TCP недоступен, UDP-протокол работает | Узел не исключается по универсальному TCP-фильтру |
| Ошибка DNS при живом транспорте | Диагностируется DNS; причина не теряется в общем timeout |
| Есть RX от старой сессии, новые запросы не идут | Активность счётчиков не маскирует частичный отказ |
| Пользователь ничего не передаёт | Простой не считается зависанием |
| Медианный RTT немного колеблется | Нет добровольных переходов |
| Другой сервер устойчиво заметно лучше | Переход только после подтверждений и срока удержания |
| Текущий отказал во время удержания | Аварийный переход не ждёт таймера улучшения |
| Смена Wi-Fi/LTE во время скана | Старые результаты отменены, не применяются к новой сети |
| Одновременный ручной выбор и Auto | Один последовательный результат; ручное действие имеет приоритет |
| Смена подписки | Сохранены ожидаемые пользовательские маршруты/DNS |
| Кандидат прошёл изолированный тест, но активный путь не работает | Не объявлять успех; откат либо поиск следующего |
| Обновление подписки удалило активный узел | Детерминированный резерв, отсутствие битых ссылок в группах/цепочках |
| Лимит одновременных соединений провайдера | Планировщик не создаёт искусственную массовую недоступность |

Тестировать Xray/mihomo и все протоколы, реально входящие в поддерживаемую матрицу. REALITY/TLS-сценарии проверять на известных версиях клиента/сервера; не приписывать всякий отказ ядру без воспроизведения.

## 4. Правила, цепочки и утечки

- Проследить домен/приложение → правило → группу → конкретный путь → DNS. Проверять IPv4, IPv6, UDP/QUIC и адрес без доменного имени.
- Для цепочки проверять данные от клиента до назначения через обе ступени; независимо успешные пинги ступеней недостаточны.
- При недоступном выходе/UDP запрещён незаявленный direct fallback.
- Provider update сохраняет overrides либо показывает конфликт; порядок правил не меняется скрыто. Проверить `TrafficRoute.order` из 0.36.1 при импорте старого backup, синхронизации и вставке нового маршрута; оба ядра исполняют ожидаемый порядок. Для Xray проверить DNS при переносе proxy-правила выше direct-правила.
- На Linux сохранить исправление прав файлов/каталогов пакетов 0.36.1; на Windows проверить установщик/portable, обновление и изоляцию данных Orrdroid от Keqdroid.
- Ошибка загрузки hosts сохраняет последнюю рабочую версию; слишком большой список не выводит клиент из строя.
- Проверить исходящий адрес и DNS на переключении, падении/восстановлении ядра и обновлении конфигурации.
- Проверить local SOCKS/API с другого приложения и рабочего профиля: IPv4/IPv6, собственный/чужой/неизвестный UID. Фиксировать границы платформы; успешный тест на одной ROM не является общей гарантией.
- RKNHardering использовать для отдельных проверок. Его общий вердикт не подменяет проверку утечек или доказательство невозможности обнаружения VPN.

### Пресеты БС и ЧС

| Сценарий | Ожидаемое действие |
|---|---|
| БС, домен в мобильном белом списке и `geosite:ru`, IP в `geoip:ru` | DIRECT. Белый список стоит непосредственно перед правилом российского выхода |
| БС, только `geosite:ru` или только `geoip:ru`, белого списка нет | Выход в РФ. Проверить оба совпадения независимо и подключение по IP, включая IPv6 |
| БС, выход с меткой РФ фактически вне РФ или страна неизвестна | Кандидат не проходит допуск. Проверить одиночный путь и последнюю ступень цепочки |
| ЧС, обычный российский или иностранный сервис вне подходящих правил | DIRECT |
| БС, запрос вне подходящих правил | Текущий сервер |
| Чистая установка, детектор Farvater не определил режим | Доступны разрешённые источники всех режимов. Активны правила «Всегда» и обычное действие «Всё остальное» |
| Импорт старого правила без «Когда» | «Всегда», с прежним порядком и действием |
| Один TUN, текущий сервер и отдельная фиксированная цель | Два одновременных потока используют назначенные выходы. Проверить публичный IP каждого и соответствующий DNS |
| В поле «Куда» выбрана сохранённая цепочка | После сохранения и повторного открытия правила цепочка выбрана по стабильному ID. Совпавший поток проходит через все ступени, другой поток сохраняет назначенный ему выход. Проверить через mihomo |
| Назначенная цепочка недоступна, удалена или несовместима с ядром | Редактор или состояние маршрута показывает причину. Действует явно настроенный допустимый резерв либо блокировка. Проверить, в частности, ограничение штатного формата цепочек на Xray в v0.36.1 |
| IP-проверка отдельного выхода | Ответ Cloudflare trace получен через тот же выход, который проверяется, включая последнюю ступень цепочки |
| ЧС, блокировка РКН и отдельно замедление РКН | Прокси, в каждом случае проверка выбранного пути по профилю сервиса |
| ЧС, запрет доступа из РФ, включая пересечение со списками РКН | Проверенный выход вне РФ и доступ к самому сервису |
| Нужного выхода нет или проверка назначения не прошла | Статус «нет подходящего маршрута» для затронутых соединений |
| БС → ЧС → БС и обновление списков | Новые потоки следуют применённому режиму. Устаревшие проверки не меняют выбор. При ошибке загрузки остаются действующие списки |

### Ранняя проверка R1

До выпуска с заявленной строгой изоляцией выполнить матрицу [SECURITY_ISOLATION.md](SECURITY_ISOLATION.md): allProxy/include/exclude в разных профилях; отказ owner service; системный DNS и DoT; ICMP/фрагменты; кеш 5-tuple; нагрузка и входящие Tailnet-соединения. Существующие owner-патчи Keqdroid считать исходной базой, а не подтверждённой полнотой защиты. Проверить, что итоговый бинарник собран с ними. Видимость tun0 и отсутствие передачи через него учитывать раздельно.

### Наблюдение от 11 ноября 2026

[Разбор предоставленного скана и backup](SCAN_2026-11-11.md) подтверждает необходимость раздельных статусов. Видимый tun0 и успешный setsockopt не равны передаче данных; в скане активные TUN-пробы не прошли. Для отрицательных проб обязателен положительный контроль доступности той же цели, для положительных — nonce/ответ и журнал контролируемого сервера. Отсутствие результата остаётся unknown. Проверять одно устройство в том же и другом профиле, allProxy/include/exclude и оба ядра.

Добавить синтетическую миграцию пяти маршрутов без order и сохранение вычисленного порядка после повторного экспорта. Одна сервисная цель (в предоставленной настройке Instagram favicon) не определяет глобальную работоспособность всех узлов; отдельно проверять общий доступ и полную передачу тела по фактическому активному маршруту.

## 5. Синхронизация

### Режим главного устройства

| Сценарий | Условие прохождения |
|---|---|
| Главное изменило подписку/правило | Все доступные назначенные ведомые получили одну проверенную ревизию |
| Ведомое пытается отправить свои настройки | Главное не принимает изменение; hash его конфигурации прежний |
| Ведомое подделало/изменило snapshot | Подпись/целостность не проходит, конфигурация не применяется |
| Устройство состоит в Tailnet, но не сопряжено | Секреты и конфигурация недоступны |
| Replay старой подписанной ревизии | Отвергается по эпохе/счётчику; часы не решают конфликт |
| Главное выключено | Ведомые работают со старой конфигурацией, не выбирают нового издателя |
| Длительный офлайн ведомого | Применяется последняя совместимая ревизия после возвращения |
| Обрыв передачи / падение в момент применения | Нет частичного смешанного документа; сохранён рабочий снимок |
| Неподдерживаемое ядро/правило на ТВ или компьютере | Понятная ошибка/ожидание; нет молчаливого ослабления маршрута |
| Auth key истёк/отозван | Повторная авторизация без удаления рабочей proxy-конфигурации |
| Смена главного владельцем | Одна новая эпоха и один издатель, старые публикации не принимаются |
| Подмена запроса «сделать меня главным» ведомым | Не меняет полномочия |
| Отзыв устройства | Новые snapshots не выдаются; ограничения старых копий документированы |
| Обновление AWG-параметров | Не теряется единственный путь доставки; есть staged activation/восстановление |
| Синхронизация при активном VPN на Android | Не запускает конкурирующий VpnService и не обрывает его ради простого чтения настроек |

Проверять сначала Android ↔ Android, затем Android ↔ Windows/Linux и Android TV. На главном телефоне отдельно измерить доставку при screen-off/Doze. Если платформа не обеспечивает постоянную доступность listener, это явно отражается в статусе, а не объявляется мгновенной синхронизацией.

## 6. Tailnet/AWG

Для LiuTangLei фиксировать релиз ядра и мобильной обвязки, а также точные зависимости WireGuard/QUIC/uTLS. Прогон: обычные peers, оба peers с согласованным AWG, несовпадающие профили, direct/DERP, IPv4/IPv6, TCP/UDP, DNS, auth expiry, смена сети, рестарт и восстановление state.

Не считать `tailscale ping` доказательством работы прикладной передачи. Нужны HTTPS/файл/UDP к Tailnet-назначению и отдельная проверка доставки подписанного конфига. Совместимость control plane проверяется отдельно от data plane.

Не переносить node state между устройствами; проверить уникальность идентичности. Встроенный AWG Keqdroid и AWG форка Tailscale тестируются как разные реализации. Наличие похожих полей конфигурации не является доказательством полной совместимости.

## 7. Выпуск

Предварительные количественные ворота для Auto-части M3 ниже. Alpha первого этапа дополнительно требует всей матрицы §0.

- Все детерминированные сценарии безопасности переходов и миграции проходят; нет утечек/потери конфигурации в проверенной матрице.
- На контролируемом отказе при живой сети и заранее проверенном резерве целевой p95 восстановления ≤30 секунд. Для Doze/OEM условия и результаты публикуются отдельно; недостигнутый порог не скрывается средним значением.
- Восьмичасовой прогон стабильной сети не даёт ложных аварийных переключений; добровольные переходы укладываются в политику.
- 24–48 часов смешанной нагрузки со screen-off, Wi-Fi/LTE и рестартами без необратимого зависания и роста числа процессов/памяти.
- Суточные расходы проверок и батареи измерены относительно базового Keqdroid. Начальный ориентир — не более 10% относительного роста расхода энергии в одинаковом сценарии; принять/изменить бюджет только по данным M0.
- Трафик диагностики ограничен настройкой; исчерпание бюджета останавливает исследовательские/скоростные сканы, сохраняя минимально необходимую диагностику активного пути с отдельным учётом.

Для beta: повторение на нескольких OEM/версиях Android и минимум неделя реального использования с журналом причин отказов. Для стабильного выпуска: улучшение доступности/восстановления без регрессии ложных переходов, критических маршрутов и локальной защиты. Все изменения после измерений требуют повторения затронутых сценариев, а не бесконечного прогона всего набора без причины.

Для M3S-A (режим главного) отдельные ворота: 100% запрет обратной записи в перечисленных негативных тестах, атомарность применения, проверенная подпись/anti-replay, два разных типа устройств и восстановление после офлайна. Это не заменяет внешний аудит криптографического протокола перед широкой публикацией.

## 8. Новые сценарии редакции 0.4

### Режим всех устройств и каналы

| Сценарий | Условие прохождения |
|---|---|
| Телефон меняет подписку, ПК — другое правило в офлайне | После связи обе правки сохранены на всех участниках |
| Одно поле изменено независимо | Детерминированный результат, видимый конфликт и возможность восстановить обе версии |
| Часы ушли вперёд / старый snapshot загружен позже | Нет перезаписи всей конфигурации по mtime; причинные версии и карантин аномалий |
| Удаление объекта, затем возвращение старого устройства | Объект не воскресает; tombstone/checkpoint соблюдены |
| Одновременные перестановки правил | Валидный целый порядок; конфликт не даёт случайного direct-маршрута |
| Delete группы одновременно с правкой ссылающегося маршрута | Нет битой частично применённой конфигурации; last-known-good |
| Повтор/перестановка пакетов через LAN и Tailnet | Идемпотентность и одна итоговая версия |
| Одновременные WebDAV/S3 uploads, конфликтные копии, rollback сервиса | Нет потерянных операций; проверены подписи, версии и completeness manifest |
| Отзыв устройства / смена режима | Старые операции не повышают полномочия и не обходят новую эпоху |
| Ведомое импортирует backup с более новыми часами | Главное и управляемый слой не переписываются |
| LAN discovery чужого устройства | Нет автоматического сопряжения/выдачи секретов |
| Два provider refresh с разной выдачей UA/HWID | Снимки не смешиваются по узлам; конфликт/платформенный слой явны |
| Получено, но ядро не применило | UI не заявляет полную синхронизацию, рабочая версия сохранена |

Тестировать оба режима отдельно: проверка запрета обратной записи относится к режиму главного, а разрешённые multi-writer операции — к режиму всех устройств. Проверить реальный сон телефона, восстановление, удалённый отзыв и шифрованный offline backup.

### LAN-прокси

| Сценарий | Условие прохождения |
|---|---|
| Нет логина/пароля или они неверны | Ни SOCKS CONNECT/UDP, ни HTTP/CONNECT не дают доступ |
| Клиент предлагает SOCKS no-auth | Метод отклонён, авторизация обязательна |
| Корректный клиент | Проверенный ответ/тело через выбранный путь; DNS и IPv6 соответствуют политике |
| Смена узла, падение ядра, пустая группа | Нет скрытого direct fallback; состояние клиента объяснимо |
| @, :, Unicode, %, IPv6 в реквизитах | URI и QR корректно декодируются совместимым клиентом, есть ручные поля |
| Смена LAN/мобильная сеть/сон | Listener не становится публичным; адрес/QR актуальны либо доступ остановлен |
| Смена пароля | Старые ссылки отвергнуты; политика существующих сессий соблюдена |
| Sync/backup на другом устройстве | Раздача не включается автоматически; локальные credentials не клонируются |
| Доступ к control API и sync endpoint через раздачу | Не публикуются; аутентификация proxy не даёт административных прав |
| Чужой TUN при включённой LAN-раздаче | UID-защита не ослаблена; разрешённый LAN inbound работает отдельно |

### Регрессии из анализа backup/issues

- REALITY: одинаковые параметры и DNS, матрица клиент/сервер/fingerprint, структурированная ошибка handshake.
- Подписки: число полученных/импортированных узлов, UA/формат, сохранение provider DNS и маршрутов; секреты не выводятся.
- Auto: результаты применяются без принудительного удаления узлов; удаление/refresh во время health check не даёт устаревшего callback или падения.
- Сервис вернул 403/редирект/обрезанное тело: отдельно доступность узла и соответствие сервисному профилю.
- Неподходящая страна с лучшим RTT: исключение сохраняется; если других узлов нет, нет молчаливого выбора запрещённой страны.
- Длительные connect/disconnect, память, crash-log rotation, сутки работы; закрытый issue не заменяет эти измерения.

- Одинаковое имя узла в двух подписках: выбранный ID и цели маршрутов не меняются при добавлении второй подписки, сортировке или синхронизации.
